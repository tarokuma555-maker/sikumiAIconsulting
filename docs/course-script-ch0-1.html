第0章 この講座で、どこまでやるか

全3本・約15分 ／ 到達点:何ができるようになるか、何はやらないかを受講者が理解している

この章のねらい

ここは期待値を合わせるための章です。「3ヶ月で業務が全部自動化される」と思ったまま進むと、 最後に不満が残ります。やらないことを先に言うのが目的です。

0-1 ようこそ。これは「AIの使い方講座」ではありません
約5分顔出し画面なし
話すこと

はじめまして。シクミAIコンサルの大熊太郎です。この講座を選んでいただいて、ありがとうございます。

最初にお伝えしておきたいことがあります。これは「AIの使い方を覚える講座」ではありません。 あなたが毎週やっている面倒な作業を1つ選んで、それをAIに任せる形を作るための講座です。

違いは何かというと、順番です。ふつうは道具の使い方から入りますよね。でもそれだと、 使い方を覚えたあとで「で、これを何に使うんだっけ」で止まってしまう。私も最初そうでした。 なので、この講座では先に「これを楽にしたい」を決めてから、道具を触ります。

私自身、最初の仕事は飲食店の店長でした。パソコンとはほぼ無縁の現場から、営業、労務の相談役を経てIT業界へ。 いまは大きなシステムを作り替えるプロジェクトで、現場とエンジニアの間をつなぐ仕事をしています。 つまり私も、もともとは非エンジニアです。 どこでつまずくかは、自分の体験として分かっているつもりです。

0-2 この講座でやること・やらないこと
約6分顔出し＋スライド最重要
話すこと

この講座を見終わったときに、あなたができるようになっていることは4つです。

1つめ。自分の仕事の中から「AIに任せられそうな作業」を3つ挙げられる。
2つめ。自分のパソコンでClaude Codeを動かして、日本語で指示が出せる。
3つめ。用意したひな形を使って、1つの作業の下書きをAIに作らせられる。
4つめ。うまくいかないときに、自分で直す手順を持っている。

逆に、この講座がやらないこともはっきり言っておきます。

あなたの業務に合わせた設計は、この講座には含まれません。 動画は、私が用意した例で進みます。あなたの会社の事情、扱っている情報の種類、 上司への説明の仕方——そういう個別のことは、動画では扱えません。

そこまでやりたい方のために伴走プランがあります。ただ、 まずはこの講座を一周してみてください。ひとりで最後まで行ける方も多いはずです。 行けなかったところが分かってから相談したほうが、話が早いです。

進め方です。順番に見てください。とばすと後半で困ります。 とくに第2章で「任せる作業」を決めてから第3章に進むのが大事です。

見るだけでは身につきません。第2章と第4章には、実際に手を動かす回があります。 そこは動画を止めて、自分でやってから先に進んでください。

用意していただくものは3つです。ひとつ、インターネットにつながるパソコン。 WindowsでもMacでもかまいません。ふたつ、Claudeのアプリ。無料でダウンロードできます。入れ方は第3章でやります。 みっつ、AIの利用料。これは受講料とは別に、月に数千円ほどかかります。 無料で試せる範囲もあるので、そこも第3章でご案内します。

それから、質問について。動画の内容についてのご質問を、30日間お受けします。 「この手順のとおりにやったが動かない」といったものです。窓口はメールで、平日3営業日以内にお返しします。 あなたの業務そのものをどう設計するかというご相談は、伴走プランの範囲になります。

では、始めましょう。

第1章 仕事でAIを使うための基礎

全7本・約60分 ／ 到達点:AIに向く仕事と向かない仕事を、自分で判断できる

この章のねらい

ここでは、まだClaude Codeを触りません。先に「AIに何をどう頼むか」の考え方を入れます。 道具を触る前に頭ができていないと、第3章で手が止まります。

順番も意図的です。「苦手なこと」を先に見せます。 できることから見せると期待が上がりすぎて、最初の失敗で心が折れます。

1-1 AIが苦手なこと
約8分画面録画先に苦手から
話すこと

まず、AIが苦手なことから話します。順番が逆に思えるかもしれませんが、 ここを先に知っておくと、あとで無駄に悩まずに済みます。

ひとつめ。AIは、平気で間違えます。しかも、間違えるときも自信たっぷりに答えます。 「たぶん違うかも」とは言ってくれません。だから出てきたものを人が確かめる工程は、必ず要ります。

ふたつめ。AIは、あなたの会社の事情を知りません。 社内の言い回し、暗黙のルール、この人にはこう書くという配慮。教えなければ分かりません。

みっつめ。AIは、責任を取れません。間違ったまま出した資料の責任は、出した人にあります。

ここから分かるのは、最初にAIに任せるべき作業の条件です。 間違いに気づける作業。取り返しがつく作業。この2つを満たすものから始めます。 いきなり「お客様に直接送るメール」を任せてはいけません。

画面
  • スライド:「AIが苦手な3つ」
  • 実演:わざと間違った答えを出させて見せる(もっともらしく間違える様子を見せるのが目的)
  • スライド:「最初に任せる作業の2条件——間違いに気づける／取り返しがつく」
1-2 AIが得意なこと
約7分画面録画
話すこと

では得意なことです。ひとことで言うと、「決まった形に整えること」です。

散らばったメモを1つにまとめる。長い文章を短くする。同じ形式に揃える。 表から数字を拾って集計する。ファイルの名前を規則どおりに付け替える。 どれも、あなたが手でやれば必ずできるけれど、時間だけかかる作業です。

逆に言うと、あなたにしかできない判断は、AIには渡せません。 「この案件、今週報告すべきか」といった判断です。 そこはあなたが持ったまま、その手前の下ごしらえだけを渡す。これがこの講座の考え方です。

画面
  • スライド:「得意なこと=決まった形に整えること」+ 具体例5つ
  • スライド:「渡すのは下ごしらえまで。判断は自分が持つ」——第4章の図と同じ絵にする
1-3 お願いの書き方——3つ入れるだけ
約10分画面録画この章の核
話すこと

ここがこの章でいちばん大事なところです。AIへのお願いには、3つ入れれば足ります。

1. 何を——材料です。「このフォルダの先週分の会議メモを」
2. どうしてほしいか——してほしいことです。「まとめて、報告書の下書きにして」
3. どんな形で——出来上がりの形です。「先月の報告書と同じ形で」

この3つです。難しい言葉は要りません。人にお願いするときと同じです。 新しく入った人に仕事を頼むところを想像してください。材料を渡して、何をしてほしいか言って、 出来上がりの見本を見せる。それと同じことをします。

よくある失敗が、3つめを言わないことです。「まとめておいて」だけだと、 AIは自分の好きな形でまとめます。それが自分の欲しい形と違うので「使えない」となる。 見本を見せるのが、いちばん手っ取り早いです。

画面
  • スライド:「3つ入れるだけ」——何を / どうしてほしいか / どんな形で
  • 実演:3つめを抜いた頼み方 → 期待と違う結果
  • 実演:3つめを足した頼み方 → 期待どおりの結果
  • 同じ材料で2回やって、差だけを見せるのがポイント
1-4 思ったとおりに出ないときの直し方
約9分画面録画
話すこと

思ったものが出てこなかったとき、最初から書き直す必要はありません。 そのまま「ここをこうして」と続けて言えば直ります。会話の続きとして直せる、というのが大きな特徴です。

直し方には順番があります。まず、どこが違うのかを具体的に言う。 「なんか違う」では直りません。「長すぎる」「この項目が抜けている」「もっと固い言葉で」。 具体的に言うほど、まっすぐ直ります。

それでも直らないときは、いったん諦めて、頼み方を変えます。 同じ言い方で3回粘るより、材料の渡し方や見本を変えたほうが早いことが多いです。

それから、これは覚えておいてください。途中でおかしくなったら、新しく始め直す。 長く続けたやりとりは、だんだん噛み合わなくなることがあります。そういうときは、 うまくいっていたところまでの内容を持って、新しく始めたほうが早いです。

画面
  • 実演:「なんか違う」と言ってみる → 直らない様子
  • 実演:「長すぎるので半分に。あと日付を入れて」→ 直る様子
  • スライド:「直し方の順番——具体的に言う → 頼み方を変える → 始め直す」
1-5 会社の情報を、そのまま渡さない
約12分画面録画いちばん質問が来る
話すこと

ここは慎重に話します。「会社の情報をAIに入れて大丈夫なのか」—— いちばん多い心配だと思います。

まず前提として、これは会社ごとにルールが違います。 「大丈夫です」と私が言い切れる話ではありません。なので、 ルールを確かめる方法と、そもそも渡さずに済ませる方法の2つをお伝えします。

渡さずに済ませる方法は、大きく2つです。ひとつは伏せる。 会社名を「A社」、人の名前を「担当者」、金額を「◯円」に置き換えてから渡す。 形を整えてもらうだけなら、中身が本物である必要はありません。

もうひとつは作りものを使う。本物そっくりの、でも中身は架空のデータを用意して、 それで仕組みを作る。できあがってから、本物を通す。 作っている最中に本物を渡す必要はない——これは意外と知られていません。

そのうえで、会社のルールが分からない場合。確認するとよいのは3つです。 生成AIの業務利用について決まりがあるか。使ってよいサービスが決まっているか。 持ち出してはいけない情報の種類が定義されているか。 この3つを情報システム部門か上長に聞けば、たいてい話が進みます。

最後に、これだけは。お客様の個人情報と、まだ公表していない数字。 この2つは、判断がつかないうちは渡さないでください。

画面
  • 実演:本物っぽい資料 → 伏せたあとの資料。並べて見せる
  • スライド:「確認する3つの質問」——そのまま上長に送れる文面にしておく
  • スライド:「判断がつかないうちは渡さない2つ」
注意
  • 特定のAIサービスの規約内容を断定しないこと。規約は変わります
  • 「安全です」と言い切らない。「会社のルールを確かめてください」で通す
  • 実演に使う資料はすべて架空のものを新規に作ること
1-6 ひな形集の使い方
約7分画面録画
話すこと

この講座には、ひな形集が付いています。ゼロから考えなくていいように用意したものです。

使い方は、コピーして、かぎ括弧の中を自分の言葉に置き換えるだけです。 たとえば報告書のひな形なら、「〔材料のある場所〕」「〔出したい形〕」というところを埋めます。

ここで1-3の話とつながります。ひな形は、さっきの3つが最初から入った状態です。 何を・どうしてほしいか・どんな形で。埋めるところが3つあるのは、そのためです。

慣れてきたら、自分用に書き換えてください。ひな形は完成品ではなく、出発点です。

画面
  • ひな形集を実際に開いて、中身を見せる
  • 1つを選んでコピーし、かぎ括弧を埋めるところまで実演
  • 埋めたものが1-3の「3つ」に対応していることを、色分けなどで示す

伝えるべき違いは「アプリかブラウザか」ではありません。「ローカルかクラウドか」です。 Claude Codeのセッションには、自分のパソコンで動くローカルと、 Anthropicの別のマシンで動くクラウドがあり、 この講座で使えるのはローカルだけです。

やっかいなのは、デスクトップアプリを入れてもクラウドを選べてしまうことです。 「アプリを入れれば大丈夫」では足りません。環境を「ローカル」にする操作まで見せて、はじめて完了です。

見分け方はプロンプト欄の左端のボタンです。「ローカル」と出ていれば正解で、次に選ぶのはフォルダ。 環境名(「デフォルト」など)が出ていて、その右にリポジトリ名とブランチ名が並んでいたら、それはクラウドです。

クラウドを選ぶと、パソコンのファイルに触れないだけでなく、 アプリ内のターミナルもファイル一覧もプラグインも使えなくなります(いずれもローカル専用)。 受講者は原因が分からないまま止まります。3-1で概念を、3-4で実際の操作を、2回に分けて潰してください。
